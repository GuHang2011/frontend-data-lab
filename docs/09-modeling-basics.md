# Modeling basics | 从问题到模型

## 1. 先定义任务

把业务描述改写成可计算的任务：

| 问题 | 典型任务 | 输出 |
| --- | --- | --- |
| 请求属于哪类事务 | 多分类 | 类别概率与最终标签 |
| 是否需要人工复核 | 二分类 | 风险分数与阈值 |
| 下周请求量是多少 | 回归或时间序列 | 预测值与区间 |
| 哪些因素影响处理时长 | 描述性分析/因果探索 | 特征关系与限制 |

任务定义决定标签、切分方式和指标。模型名称应当排在这些决策之后。

## 2. 建立基线

先做一个可解释的基线，例如多数类、规则、线性模型或逻辑回归。基线回答两个问题：数据是否包含信号，以及复杂模型是否真的带来收益。

## 3. 保持数据切分诚实

- 随机切分适合近似独立同分布的数据。
- 时间预测应按时间切分，不能让未来记录进入训练集。
- 同一用户、同一事务或同一文档的重复样本应放在同一侧。
- 验证集用于选择方案，测试集只在最终比较时使用。

## 4. 记录决策

每次实验至少记录数据版本、特征版本、切分规则、随机种子、模型参数、指标和失败案例。这样模型结果才能被别人阅读和复查。
