# 02 · 接口契约与错误态

即使没有后端接口，静态 JSON 也是一种接口。前端与数据管线之间必须约定字段类型、粒度、单位和失败语义。

## “数字”还不够

`revenue_cents` 是整数分；如果另一个程序突然输出元，图表不会崩溃，但数值将错一百倍。`schema_version` 与 `currency` 是机器可检查的契约，字段名称与数据字典则补充语义。当前前端还要求安全整数，防止 JavaScript 超出精确整数范围后悄悄舍入。

数据粒度是 `(day, region, channel)`，不是“一天一行”。因此前端选择“全部区域”时必须二次聚合；直接画原始数组会把一天画出多次。契约校验检查重复分组和状态计数恒等式，尽早暴露错误。

## 成功、空结果与失败分别处理

| 情况 | 页面行为 | 含义 |
|---|---|---|
| 有效数据，有匹配订单 | 正常绘图与导出 | 计算可解释 |
| 有效数据，无匹配订单 | 空态、零计数、无定义比例显示 `—` | 查询成功，但该条件下无记录 |
| 日期输入不合法 | 提示错误，保留上次有效结果，禁用导出 | 当前输入尚未应用 |
| 数据文件缺失或契约无效 | 显示错误并禁用筛选 | 无法可靠计算 |

零不等于未知。完成订单数为零时，平均订单金额没有定义；显示 `¥0.00` 会暗示确实观察到了零金额订单，因此本例用 `—`。

## 静态数据为何提供两种封装

浏览器直接从 `file://` 打开 HTML 时，`fetch` 读取相邻 JSON 可能受到来源策略限制。本例由同一次导出同时写入 JSON 与普通脚本封装 `window.DEMO_DATA = …`。页面使用脚本，读者检查 JSON；测试保证两者完全一致。

这并不是绕过权限访问数据：它只是同一份公开演示数据的静态分发方式。若数据包含私密内容，公开 JS 和公开 JSON 一样都不能提供保护。

## 扩展为 HTTP 接口时

应定义请求参数、HTTP 状态、错误码、分页、最大日期范围和服务端口径。不能把所有错误都转为 `200 {rows: []}`，那会混淆服务异常与空结果。请求失败时允许重试，但应保留错误上下文；若请求有副作用，重试还必须考虑幂等性。

进一步阅读：[MDN — HTTP response status codes](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status)、[JSON.parse](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/parse)。
