# 03 · 性能与无障碍一起设计

可视化不是一张供人观看的图片。用户需要能读出指标、理解单位、操作筛选，并获得图形表达之外的同等信息。

## 先控制工作量，再讨论优化

默认样本有 12,000 条原始订单，但页面只收到按日期、区域和渠道聚合的几百行数据。减少传输和计算粒度通常比在浏览器中优化十二万次循环更有效。此项目仍把整个聚合快照加载到内存，不适合无限增长的数据集。

`filterRows` 与 `summarize` 是线性扫描，日历补零按日期跨度线性增长。区域构成只有三个区域，因此额外扫描容易理解；若维度扩展到数千个键，可改为一次遍历维护 Map，再测量是否改善。不要为没有观察到的问题增加缓存失效逻辑。

明细默认显示十四行，但 CSV 始终导出完整筛选结果。分页、虚拟列表和服务端聚合解决的问题不同：前两者主要减少 DOM 节点，后者减少网络与浏览器所需的数据量。

## 这里已经实现的可访问性

- 所有筛选都有可见的 `label`，按钮使用原生 `button`。
- 键盘焦点使用明显轮廓；跳转链接可绕过侧栏。
- SVG 有标题与描述，完整数值可在 HTML 表格中读取和下载。
- 区域比例同时展示文字，理解结果无需单独依赖颜色。
- 筛选结果使用礼貌级别的状态播报，不自动抢夺焦点。
- 小屏幕表格在自己的容器内横向滚动；减少动态效果偏好会关闭过渡。

这些是具体实现，**不等于已经通过 WCAG 合规审计**。需要读屏器和真实键盘流程验证，不能只根据 HTML 标签判断体验。

## 建议的测量方法

1. 记录浏览器版本、设备、数据行数与日期跨度。
2. 在 Performance 面板观察筛选操作的主线程耗时，重复多次，报告中位数与高分位。
3. 用键盘完成区域切换、日期修改、错误恢复、导出与重置。
4. 检查 320px 视口、200% 缩放、对比度和系统减少动态效果设置。
5. 用 NVDA/VoiceOver 检查焦点顺序与状态播报，记录具体问题。

本仓库没有填写虚构的 Lighthouse 分数或性能提升百分比。若后续测量，应一并保存环境、过程与原始结果。
